# Workflow: Создание нового эндпоинта

При получении задачи на создание нового API эндпоинта, действуй строго по следующим шагам:

1. **DTO (Data Transfer Objects):**
   - Создай Pydantic v2 схемы для Request и Response в файле `schemas.py`.
   - Опиши строгую валидацию (например, вес > 0, пульс > 0).
   - Для полиморфных метрик (силовые/кардио упражнения в `JSONB`) используй Discriminated Unions (`Annotated[Union[...], Field(discriminator=...)]`).

2. **Service Layer (Бизнес-логика):**
   - Реализуй бизнес-логику в `services.py`.
   - Сервис принимает валидированные DTO от роутера, вызывает репозиторий и возвращает Response DTO (не привязываясь к HTTP объектам FastAPI).
   - Если операция мутирует данные в Workout Service, сервис формирует контракт события (из пакета контрактов) для сохранения в Outbox.

3. **Repository Layer (Работа с БД):**
   - Напиши асинхронный метод в репозитории с использованием SQLAlchemy 2.0 (`select()`, `insert()`, `update()`).
   - Для Workout Service: сохранение сущности тренировки и записи в таблицу `outbox` ОБЯЗАТЕЛЬНО выполняется в рамках одной транзакции (`async_session`).

4. **Controller/Router Layer:**
   - Зарегистрируй эндпоинт в `router.py`.
   - Внедри зависимости (`Depends`), сессию БД и вызови слой сервиса.

5. **Testing:**
   - Напиши интеграционный тест в `tests/` с использованием `httpx.AsyncClient` и `@pytest.mark.asyncio`.
   - Для Workout Service обязательно проверь транзакционность Outbox:
     - При успешном запросе запись в таблице `outbox` гарантированно создается;
     - При ошибке/откате транзакции запись в `outbox` отсутствует.
   - Запусти pytest. Не отмечай задачу как выполненную, пока тесты не пройдут успешно.
