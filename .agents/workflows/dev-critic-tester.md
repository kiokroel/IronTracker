# Workflow: Мультиагентный цикл (Разработчик → Тестировщик → Критик)

Данный воркфлоу применяется для решения сложных задач кодовой базы с гарантией качества и строгой верификацией:

---

## 1. Фаза Разработчика (Developer Phase)
1. **Подготовка ветки:**
   - Создай и переключись на новую ветку по правилу `04-git-flow.md`: `<type>/<task-id>-<short-description>`.
2. **Реализация:**
   - Изучи кодовую базу и архитектурные ограничения в `.agents/rules/`.
   - Внеси изменения в код с соблюдением требований (Python 3.12+, FastAPI, SQLAlchemy 2.0 async, Pydantic v2, Transactional Outbox).
   - Подготовь краткий отчет: какие файлы изменены и суть решения.

---

## 2. Фаза Тестировщика (Tester Phase)
1. **Запуск проверок окружения:**
   - Запусти линтер и форматирование: `ruff check .`
   - Запусти статический анализатор типов: `mypy --strict .`
   - Запусти тесты: `pytest`
2. **Анализ результатов:**
   - Если тесты упали или линтер нашел ошибки — сформируй отчет с точным трейсом ошибок (stack trace).
   - При необходимости дополни тесты (граничные случаи, негативные сценарии).
   - Запрещено завершать этап, пока тесты не станут зелеными.

---

## 3. Фаза Критика (Critic Phase)
1. **Строгий архитектурный аудит:**
   - Проверь отсутствие Dual Write (используется ли Transactional Outbox).
   - Проверь валидацию JSONB через Discriminated Unions в Pydantic v2.
   - Проверь асинхронность I/O (asyncpg, motor, redis.asyncio).
   - Проверь чистоту кода и отсутствие забытых отладочных принтов.
2. **Вердикт:**
   - **`VERDICT: APPROVED`**: Код соответствует стандартам проекта, тесты зеленые. Переходи к согласованию коммита с пользователем.
   - **`VERDICT: REJECTED`**: Нумерованный список замечаний и возвращение на фазу Разработчика.

---

## 4. Финализация (Автоматический Commit, Push и Pull Request)
1. Как только изменения утверждены (получен `VERDICT: APPROVED` и подтверждение):
   - Автоматически добавить файлы и создать коммит по Conventional Commits: `<type>(<scope>): <subject>`.
   - Автоматически выполнить пуш ветки в репозиторий: `git push -u origin <branch>`.
   - Автоматически создать Pull Request в ветку `main` через GitHub MCP с подробным Markdown-описанием (Summary, QA Report, Architecture Compliance).
   - Перевести статус карточки в Notion на `Done`.
